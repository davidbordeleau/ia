# Workspace runtime specification

## Boundary

`@inventarch/workspace-runtime` is the generic workspace runtime. It owns workspace capture and adoption, captured resources, projections, publication and candidates, templates, lifecycle, authoring index and manifest, installed catalog and source policy, sources, the local store and adapters, and the host files generated from authored records (W01). The composition compiler (catalog, compile, compiled, execution, fields, inputs, installed read, task capture, task context declaration, task teaching closure, draft tools) stays in `@inventarch/agent-composition-system`, which depends on this package. There is no reverse edge: no module here imports `@inventarch/agent-composition-system`, and `tests/boundary.test.ts` fails if one appears.

`installedImplementationDigest` pins the installed bytes of this package and its fixed first-party dependencies. An upper package pins its own installed entrypoint by passing it as an additional entry; the entries are never record- or model-supplied paths. Each pinned package directory is walked within the steward hook implementation bounds (depth 16, 2,000 entries, 8 MiB per code file and 32 MiB per package); a larger tree or a nonregular code file is refused with `IA-CORPUS-DENIED`, never truncated, and `tests/installed-catalog.test.ts` exercises each bound. Each code file is opened once and read through the descriptor whose size was bounded; a file that grows while it is read, or an entry swapped for a link, socket or device after its directory was read, is refused with the same code.

## Host generation

W01. Agent files from authored agent profiles (2026-10-09, position-and-projection §4; milestone generation-binding task generation-agent-profile, plan amendments C5, C6, C7 and C12): `src/generate/agent-profile.ts`, exported through `src/generate/index.ts` on the `./internal/generate` subpath only, publishes `generateAgentProfiles(reader, within, host)` with the `GeneratedFile` and `GeneratedWord` types. For `claude` it returns, by identity, one frozen `{path, text, identity, word: 'agent-profile'}` per `@agent-profile` at band 100 that the scope token `within` admits, `path` being `.claude/agents/<profile name>.md`. The band is the only filter. A profile below band 100, where an installed or adopted base places its records, renders nothing, so a consumer's public vocabulary never becomes an agent; no system steward does either, a steward being an `@agent` (design §4). A workspace that authors public systems, as this repository does, renders their profiles: here the public `example-profile`, which task host-consumes-generated-set decides whether this repository's own projection keeps. For `codex` it returns none: a codex agent needs an entry in `.codex/config.toml`, which holds the owned MCP block (C12). Any other host is IA-PROJECTION-INPUT-INVALID, and for either host an unknown or stale token keeps its database code, the token being read before the codex answer. The file is YAML frontmatter, `name` the JSON-quoted profile name, so a name YAML reads as a keyword (`true`, `null`) stays a string, and `description` the JSON-quoted `meaning.says` of the `@agent` its `composition.agent` names (the profile's own when that agent is not admitted in the scope); a blank line and runtime's `PACKET_MARKER` on its own line, as the skills carry it after their frontmatter (C5: the marker is how the planner will tell a generated agent from a legacy steward file); then a body read only from the records the profile's own fields reference, each resolved through the same token. The body is the title `# <name>`, the profile's `meaning.says`, its identity and its agent's; `## Mandate`, the bounds of the profile's own `composition.mandate`: its identity, then `authority.participant`, `authority.moves`, `authority.scope`, `authority.excluded-words` and `authority.covers`, each when the mandate states it, and each `execution.limit-*` it states in authored order, all as authored and never judged; or, for a profile that names none, the one line `This profile names no mandate.` (the participant's governing mandate as its fallback arrives with task host-consumes-generated-set); `## Voice`, when `composition.voice` is set, the voice's identity and each `communication.*` field it states, in authored order; `## Tools`, one line per `composition.capabilities` reference naming the capability's `composition.operations`, its `execution.effects` and the host tools those effects cover through `PROSE_EFFECT_TOOLS`, named as the claude prose catalog's default selections name them (`read` covers Read, Glob and Grep, and no other effect maps a tool), or `This profile composes no capability.`; and `## Delegates`, one line per `composition.delegates` reference when the profile states one, never refused. Generation reuses the prose catalog, the effect table and `nativeValue`, not `compileProjection`'s descriptor and publication machinery, which stays the distribution products' projector and refuses delegates (C6). A reference is printed as the identity it resolves to, or as authored when no admitted record in the scope answers it, and then the agent, mandate, voice and capability lines, whose records' fields are read, add `not admitted in this scope`; identities, references and covers paths are code spans; a field contributes only its unconditional values; and a line break in a value is printed as one space. The text is a function of the scope's records alone: it names no absolute path, time, scope token, revision or package version, so two roots holding the same records give equal files. Nothing applies the files yet: apps/cli's `renderProjectionFor`, the distribution planner, which still treats agent paths as legacy, and the steward hook are unchanged until task host-consumes-generated-set hands the generated set to `applyHostProjection` and lists it in the receipt (C4). `tests/generate-agent-profile.test.ts` lays apps/cli's composition fixture (`tests/fixtures/composition-workspace`, C7: an `ia init` workspace and an authored `@agent-profile` with a voice and a capability naming an operation, which admits over the base `ia init` installs) over the conformance corpus adopted at band 90. It pins the fixture profile's exact agent file, which names its mandate and lists its capability's operation and host tools, frontmatter first and the marker second, and the output frozen; a profile naming no mandate rendered with the one line; a named mandate's participant, moves, scope, excluded words, covers and limits; one line per delegate in authored order, each authored profile its own file by identity, and one with no mandate, voice or capability; one tools line per capability in authored order, an effect no host tool covers naming none and a repeated `read` naming its tools once; a multi-paragraph value printed on one line; under a scope narrowed to the profile, the exact file with the profile's own description and the agent, mandate, voice and capability lines saying they are not admitted, and under the whole workspace an agent no record answers saying so; the same profile adopted rendering nothing, and this repository's own workspace rendering exactly its public `example-profile`; codex rendering none, an unknown host refused, and a forged or stale token refused with its database code for either host; and equal files at two roots and under a second token, naming neither root nor token. The test reads that fixture and this repository's records through the filesystem, so workspace-runtime:test hashes them under the `composition-fixture` input profile, which adds the fixture to `workspace-records`.

W02. Execution binding (milestone generation-binding task execution-binding-host-entry, plan amendments C16 and C24): `src/bind.ts` (`./bind`) joins each `@execution-binding` with the installed-implementation catalog's operation rows, typed by `@inventarch/db/distribution`'s `InstalledOperation`. `executionBindings(reader)` reads every admitted binding with its unconditional `binding.kind`, `binding.implementation` and `binding.target`, a stated target kept as the reference written and the identity it resolves to, null when no admitted record answers it (`BindingTarget`; review finding B2-R1: a stated target is never read as no target); `bindExecution(binding, catalog)` returns `bound` only when the catalog is present, lists the implementation as available, the binding is an operation binding and its target, when it states one, resolves to the operation the implementation serves; `unavailable` when there is no catalog, it does not list the implementation, lists it unavailable, the kind has no catalog section, the stated target resolves to no admitted record (so the canonical `read-captured-source-binding`, copied into an `ia init` consumer that admits no `@operation read-captured-source`, is unavailable there) or the implementation serves another operation; `revoked`, an error, when the catalog revokes it or failed verification. The catalog is the one `@inventarch/distribution` read from the verified host payload; this package never imports the composition system, and nothing is loaded or executed.

## Provenance

Moved from @inventarch/agent-composition-system on 2026-10-06 (inventarch/ia#16). The moved modules keep their names and behaviour, except that the installed catalog now takes additional entries and bounds its walk; `@inventarch/agent-composition-system` keeps the moved root symbols and every moved subpath, `./internal/*` included, as plain aliases that forward here until its next major.
