# @inventarch/workspace-runtime

The generic workspace runtime: workspace capture and adoption (`captureWorkspace`, `adoptWorkspace`, `verifyCapture`, `Corpus`), captured resources and native resource context, projections and prose catalogs, managed publication and candidate validation, captured template rendering, lifecycle rows, profiles and transport, the authoring index and manifest, the installed catalog digest and installed source policy, source policies, the local store adapter and installed adapter verification. [SPEC.md](SPEC.md) owns the boundary.

Consumers import the package root for capture, publication, candidate validation and the installed implementation digest, and the public subpaths (`/resources`, `/projections`, `/templates`, `/lifecycle`, `/lifecycle-profile`, `/authoring`, `/authoring-manifest`, `/sources`, `/local-store`, `/adapters`, `/corpus`, `/installed-catalog`, `/authoring-types`, `/authoring-format`, `/resource-format`, `/resource-sources`, `/task-capture-format`, `/candidate`, `/publication`) for the rest. `./internal/*` entries exist for every emitted top-level module and are not a stable contract. `./internal/generate` serves the host generators, which render host files and definitions from a workspace's authored records and report each authored record they do not render with the reason: `generateAgentProfiles` one claude agent file per authored `@agent-profile` (SPEC W01), `generatePlaybookSkills` one skill per authored `@playbook` for claude or codex (W02), `generateHookSet` the authored `@hook` declarations the `@mandate` edit guard can decide (W03), and `generateDefinitions` the authored `@operation` and `@harness` definitions (W04), and `renderPlugin` the host plugin a product `@distribution` describes (W05). `./internal/host-plugin` serves `ia init --from` and `ia project --product plugin`: it reads a host plugin, lowers it into records and compares a rendered plugin with the original (W06), and like every `./internal/*` entry it is not a stable contract.

This package never imports `@inventarch/agent-composition-system`. The composition compiler lives there and depends on this package.

Nothing applies these outputs yet: the CLI's single projection writer takes them up in milestone generation-binding task host-consumes-generated-set. An operation's handler and validator ids are catalog keys, never imported or executed here. A profile that names no mandate falls back to the authored mandates that bind its agent, as the edit guard judges it.
