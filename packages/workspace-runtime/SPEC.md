# Workspace runtime specification

## Boundary

`@inventarch/workspace-runtime` is the generic workspace runtime. It owns workspace capture and adoption, captured resources, projections, publication and candidates, templates, lifecycle, authoring index and manifest, installed catalog and source policy, sources, the local store and adapters, and the host files and definitions generated from authored records (W01 to W04). The composition compiler (catalog, compile, compiled, execution, fields, inputs, installed read, task capture, task context declaration, task teaching closure, draft tools) stays in `@inventarch/agent-composition-system`, which depends on this package. There is no reverse edge: no module here imports `@inventarch/agent-composition-system`, and `tests/boundary.test.ts` fails if one appears.

`installedImplementationDigest` pins the installed bytes of this package and its fixed first-party dependencies. An upper package pins its own installed entrypoint by passing it as an additional entry; the entries are never record- or model-supplied paths. Each pinned package directory is walked within the steward hook implementation bounds (depth 16, 2,000 entries, 8 MiB per code file and 32 MiB per package); a larger tree or a nonregular code file is refused with `IA-CORPUS-DENIED`, never truncated, and `tests/installed-catalog.test.ts` exercises each bound. Each code file is opened once and read through the descriptor whose size was bounded; a file that grows while it is read, or an entry swapped for a link, socket or device after its directory was read, is refused with the same code.

## Host generation

W01. Agent files from authored agent profiles (2026-10-09, revised 2026-10-11; position-and-projection §4; milestone generation-binding task generation-agent-profile, plan amendments C1, C5, C6, C7 and C12, operator decision OD4, review findings A-R3, A-R6 to A-R9, A-RC2 to A-RC5 and N1 to N5): `src/generate/agent-profile.ts`, exported through `src/generate/index.ts` on the `./internal/generate` subpath only, publishes `generateAgentProfiles(reader, within, host)`, which returns a frozen `GeneratedSet`, `{files, unsupported}`: `files` the `GeneratedFile` rows `{path, text, identity, word: 'agent-profile'}`, `unsupported` the `UnsupportedRecord` rows `{identity, word, reason}` the projection receipt's `unsupported` section holds. Only `@agent-profile` records at band 100 that the scope token `within` admits are read, by identity; a profile below band 100, where an installed or adopted base places its records, renders nothing and is not reported, and no system steward renders, a steward being an `@agent` (design §4). For `codex` every authored profile is an unsupported row: a codex agent needs an entry in `.codex/config.toml`, which holds the owned MCP block (C12). For `claude` each profile renders `.claude/agents/<profile name>.md`, unless it is reported instead: its name is no portable host name (`safeName`: lower-case letters, digits and single hyphens, a letter first and no hyphen last, at most 64 characters, no Windows device name, `com0` and `lpt0` included); its capabilities allow no host tool (claude gives an agent with no tool list every tool, so only an unwritten file grants nothing); the composition compiler would refuse its capability closure (`closureRefusal`: an inclusion cycle, or an included capability with an effect its includer does not declare, the compiler holding each capability's own `execution.effects` as the ceiling of what it includes); or its text is not inert prose (projection-host's `inert`: no executable dynamic context, no active HTML, no unbalanced code span or fence), judged on each authored value before rendering, so the reason names what the record itself holds, and on the rendered file. One record's refusal never fails the others. Any other host is IA-PROJECTION-INPUT-INVALID, and for either host an unknown or stale token keeps its database code. A profile's capability closure is its `composition.capabilities` and every capability they include through `composition.includes`, each once (`capabilityClosure`). The file is YAML frontmatter: `name` the JSON-quoted profile name; `description` the JSON-quoted `meaning.says` of its `composition.agent` when the workspace authors that `@agent`, else the profile's own, so an installed or adopted base's text never decides when claude delegates; and `tools`, the claude names of the host tools the `execution.effects` of the profile's own `composition.capabilities` cover (each bounds what it includes, so the closure adds none) through `PROSE_EFFECT_TOOLS` (`read` covers Read, Glob and Grep; no other effect maps a tool), first-stated and each once, as one JSON-quoted comma-separated string. Then a blank line and runtime's `PACKET_MARKER` on its own line (C5), and a body read only from the records the profile's own fields reference, each resolved through the same token: the title, the profile's `meaning.says`, its identity and its agent's; `## Mandate`; `## Voice`, when `composition.voice` is set, its identity and each `communication.*` field; `## Tools`, one line per capability of the closure naming its operations, effects and host tools, after a line for each `composition.capabilities` reference no admitted capability answers; and `## Delegates`, one line per `composition.delegates` reference, never refused. `## Mandate` holds the profile's own `composition.mandate` as one list item, its identity, with `authority.participant`, `moves`, `scope`, `excluded-words`, `covers` and each `execution.limit-*` it states nested beneath it, as authored and never judged. A profile that names none falls back to C1: the authored mandates `governingMandates(reader, within, {actor})` returns for its `composition.agent` that bind it (`binds !== false`, so a mandate naming no participant is included, unless it states neither scope nor covers and so governs no path), each as such a group, after a line labelling them as the fallback and saying the guard refuses the agent where a mandate that binds another participant governs and none of these grants the move; the agent is the one a subagent acts as for the edit guard and the CLI's mandate profile (OD4), so the file states what they enforce. When none binds the line says so; when C1 cannot read a mandate (IA-RUNTIME-REQUEST-INVALID) or the agent is not an admitted `@agent`, the line says the fallback is unavailable and why. The fallback is resolved only for a rendered profile that needs it. When the profile's own mandate names a participant other than its agent, a nested line says so: the edit guard and the CLI's mandate profile judge the agent by the mandates that bind it. Free text is written with runtime's packet helpers (`inline`, `code` and `prose` on `./internal/packet-host`): on one line, each bare IA word token a code span in the body; every C0 or C1 control but tab and the folded line breaks, the Unicode line and paragraph separators and the bidirectional controls become spaces; `<!--` is written `&lt;!--`, a `!` that a rendered code span would follow `&#33;`, and a leading `<` `&lt;`, so no authored value starts a YAML or Markdown line, equals a marker line, opens a comment that hides what follows, reads as dynamic context or opens an HTML block. A reference is printed as the identity it resolves to, or as authored with `not admitted in this scope` where its fields would be read; a field contributes only its unconditional values. The text is a function of the scope's records alone: no absolute path, time, scope token, revision or package version. Generation reuses the prose catalog, the effect table, `inert` and `nativeValue`, not `compileProjection`'s descriptor and publication machinery (C6). Nothing applies the files yet: task host-consumes-generated-set hands them to `applyHostProjection` and lists them in the receipt (C4). `tests/generate-agent-profile.test.ts` lays apps/cli's composition fixture (`tests/fixtures/composition-workspace`, C7) over the conformance corpus adopted at band 90 and pins: the fixture profile's exact file, its own mandate's other-participant line included, and an empty unsupported list, frozen; the fallback naming the mandates that bind the reviewer agent and not the demo participant's, a participant-less mandate included and one that locates nowhere left out, the line for none binding, and an unavailable fallback for an admitted empty move list and for an unadmitted agent, while a profile that names its mandate and a workspace with no profile never resolve it; a named mandate's nested bounds; delegates; unsupported rows for profiles allowed no host tool, for unportable names and for text that runs a command or holds active HTML, the others still rendered; IA words, controls, separators and comment openers in free text, and an adopted agent's text kept out of the description; one tools line per capability, the tools of a profile whose capability includes another, and a closure the compiler refuses (a cycle, an undeclared included effect) reported; a `!` before a rendered span and a leading `<?` escaped, and a lone backtick reported by the value's own reason; narrowed scopes; an adopted profile rendering and reporting nothing for either host; this repository's own `example-profile`; codex reporting every profile, an unknown host refused, a forged or stale token refused; and equal bytes at two roots and under a second token.

W02. Skills from authored playbooks (2026-10-09, revised 2026-10-11; position-and-projection §4; milestone generation-binding task generation-playbook-skill, plan amendments C6, C7, C8 and C12, review findings A-R3, A-R6, N1 and N5): `src/generate/playbook.ts`, on the same subpath, publishes `generatePlaybookSkills(reader, within, host)`, which returns a frozen `GeneratedSet` with `word: 'playbook'`. Only `@playbook` records at band 100 that the token admits are read, by identity (C8, operator decision OD3): a playbook below band 100 renders nothing and stays the cells `ia position` delivers. For either host each renders one skill, `.claude/skills/<playbook name>/SKILL.md` for `claude` and `.agents/skills/<playbook name>/SKILL.md` for `codex`, with the same text, unless it is an unsupported row instead: its name is no portable host name (`safeName`), it is named `ia-authoring`, the one skill the packet renders for each host and the projection writer owns (a record's name is lowercase, so no spelling escapes this), or its text is not inert prose. The file is YAML frontmatter (`name` and `description`, the JSON-quoted name and `meaning.says`), a blank line and `PACKET_MARKER` on its own line, the title and identity, then one `## <phase>` section per phase in the cycle order orient, plan, act, learn (the language's `PHASES`), a phase with no cell left out: the primary primitive's cell first and marked `(primary)`, then the others in authored order, each with its condition's terms when it has one and its text written as W01 writes free text. The text is a function of the playbook's record alone. Nothing applies the files yet (C4). `tests/generate-playbook.test.ts` pins the fixture playbook's exact skill for both hosts, conditions and phase order, adopted playbooks rendering and reporting nothing, the reserved name reported for either host, unportable names and non-inert cells reported with the fixture's own skill still rendered, IA words and comment openers in cells, this repository's own `example-method`, refused hosts and tokens, and equal bytes at two roots.

W03. Hook declarations from authored hooks (2026-10-11; milestone generation-binding plan amendments C9, C10 and C12, review findings A-R6, G-R4, G-R7 and H-N2): `src/generate/hook.ts`, on the same subpath, publishes `generateHookSet(reader, within, host)`, which returns a frozen `{hooks, unsupported}`, `generateHooks(reader, within, host)` (its `hooks`), `hookDeclaration(node)`, and `HOOK_IDENTITY`, `HOOK_IDENTITY_LIMIT` and `registrableHook(identity)`. Only `@hook` records at band 100 are read, by identity. `hookDeclaration` narrows one to what the `@mandate` edit guard decides, a frozen `HostHookDeclaration` `{identity, event: 'PreToolUse', tools, paths, message}`: `hook.event` PreToolUse, `hook.tools` one or more of Write, Edit and MultiEdit (deduplicated, canonical spelling), `hook.paths` one to 64 workspace-relative path selections in the G06c dialect written with `/` (`registrableSelection`: none empty, absolute, escaping, longer than 512 characters, holding a `.` or `..` segment or an empty one but the last, backslashed, or holding a C0, DEL or C1 control, a bidirectional control or a Unicode line or paragraph separator; `HOOK_SELECTION_LIMIT` and `HOOK_SELECTION_LENGTH`, the bounds distribution's hook registration holds its rows to), a message that is not blank, and an identity a registration can carry on the guard's command line (`registrableHook`: a canonical `system/kind/facet/name` of the language's lower-cased name characters, at most 512 characters). A hook's name is not a host path, so `safeName` does not apply. A hook that selects no path could never deny, so it is refused rather than registered as a guard that guards nothing. Anything else is IA-PROJECTION-INPUT-INVALID naming what is unsupported. `generateHookSet` registers each hook `hookDeclaration` accepts, up to `HOOK_LIMIT` (64), and reports each it refuses, and each accepted one past that bound, as an unsupported row with its reason, so one unsupported record never blocks the others; for `codex` it registers none and reports each (C12: Codex hooks are unsupported). Tool values are never read as a regex or shell text, and nothing authored but the identity reaches a registered group: the tools and paths are validated, and the paths recorded in the registration's ownership state (distribution's guard-registration). The guard decides only the edits a hook's paths and tools select (C10): a workspace protects its governing records, the `.ia/src` sources of its hooks, mandates and profiles, by selecting them, as `paths [".ia/src/**"]` does. Steward-hook's `--hook` mode reads the record through the same `hookDeclaration`, so the guard refuses what registration reports. `tests/generate-playbook.test.ts` pins the fixture hook, codex reporting it, an adopted hook neither registered nor reported, and other tools, an escaping selection, a C1 or bidirectional control in a selection, 65 selections, a 600-character selection, a 65th hook, another event, an empty path list and a blank message each reported, with `hookDeclaration` refusing the same record, and one unsupported hook leaving the others registered and the definitions rendering.

W04. Operation and harness definitions (2026-10-11; milestone generation-binding plan amendment C11, review findings A-R5, A-R9, A-R10, A-RC5 and N7): `src/generate/definitions.ts`, on the same subpath, publishes `generateDefinitions(reader, within, host)`, which returns frozen `PacketDefinition` rows (runtime's union of `{word: 'operation', definition: OperationDefinition}` and `{word: 'harness', definition: HarnessDefinition}`), the authored (band 100) `@operation` records first, then the `@harness` records, each by identity. An operation's definition is its name, `meaning.says`, `execution.handler`, `execution.input`, `execution.output` and `execution.effects`, a field it does not state absent; the handler and the two validator ids are catalog keys an installed implementation answers, copied as authored and never imported, resolved, served or executed here (milestone 7 owns execution; the MCP door serves no new tool). A harness's definition is its name, `meaning.says`, `composition.workspace`, `execution.host-profile`, `composition.profiles`, `composition.bindings` and its registration set: the agent files rendered for its profiles, the skills rendered for the playbooks of their capability closure (W01; a closure the compiler refuses selects none), and the registered hooks its bindings' `binding.target` names, as identities and paths. A record the host does not render or register selects nothing, so hook or agent support never fails the definitions. `tests/generate-playbook.test.ts` pins both fixture rows exactly, the codex registration set, a harness whose profile reaches a playbook only through an include selecting exactly that skill and nothing of the fixture's, and nothing once the include closes a cycle, and this repository's `read-captured-source` row with handler `captured-source-read-v1` and its input and output validator ids.
